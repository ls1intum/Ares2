# Ares 2 Documentation

This site is built with [Docusaurus](https://docusaurus.io/) and published to
<https://ls1intum.github.io/Ares2/>.

It is split into two guides:

- **Instructor Documentation** (`docs/instructor/`) — for instructors and exercise authors:
  what Ares 2 protects against, how to protect a Maven or Gradle project, and how to migrate an
  Ares 1 exercise.
- **Maintainer Documentation** (`docs/maintainer/`) — for people working on Ares 2 itself: the
  technologies it is built on, the policy model, and the subsystems.

## Installation

```bash
corepack enable                  # one-time: activate the pnpm version pinned in package.json
pnpm install --frozen-lockfile
```

## Local development

```bash
pnpm start
```

This starts a local dev server and opens a browser window. Most changes are reflected live
without restarting.

## Build

```bash
pnpm run build     # static site into build/
pnpm run serve     # serve the built site locally
pnpm run typecheck # TypeScript check
```

The build runs with `onBrokenLinks` and `onBrokenAnchors` set to `throw`, so a dangling
cross-reference fails the build rather than shipping. Run `pnpm run build` before pushing.

## Writing pages

- Use the `.md` extension for ordinary prose. `markdown.format` is set to `detect`, so `.md`
  is parsed as CommonMark and bare `<` or `{` (Java generics, Gradle `${...}`) need no
  escaping.
- Use `.mdx` only when the page genuinely needs JSX or imported React components. MDX rules
  then apply to the whole file.
- Ordering in the sidebar comes from `sidebar_position` front matter and `_category_.json`
  files. Both sidebars are autogenerated, so a new page needs no edit to `sidebar-*.ts`.

## Diagrams

PlantUML sources live next to the pages that use them, and their rendered SVGs are
**committed** alongside, mirroring how the `.drawio` sources in this repository sit next to
their `.drawio.png` renders. Nothing is fetched from an external diagram server at page-view
time.

```bash
pnpm run diagrams        # re-render every .puml under docs/ to .svg
pnpm run diagrams:check  # verify the committed SVGs match their sources (CI runs this)
```

Rendering needs a JDK on `PATH`. The PlantUML JAR is downloaded once into `.plantuml-cache/`
and verified against a pinned SHA-256. Layout uses PlantUML's built-in Smetana engine, so
Graphviz is not required.

After editing a `.puml`, run `pnpm run diagrams` and commit the regenerated `.svg`. CI fails
if the two have drifted.
